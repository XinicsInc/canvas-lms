# 응시 중 브라우저 다이얼로그 → 페이지 내부 모달 전환 — 수동 QA 체크리스트

- 날짜: 2026-08-19
- 대상: **Canvas 2020 (PRT-109)** 및 **Canvas 2024 (PRT-124)** — 두 버전 공용
- 동작 계약: `docs/superpowers/specs/2026-08-18-PRT-109-spec.md` (§4 수용 기준 AC1–AC11)
- 2024 실행 계획: 2024 워크트리 `docs/superpowers/plans/2026-08-19-PRT-124-plan.md`

## 이 문서를 두 버전에 함께 쓰는 방법

동작 계약이 두 버전 공통이므로 대부분 항목은 그대로 적용된다. **기대 결과가 버전별로 갈리는 항목에만 태그**를 달았다.

| 태그 | 뜻 |
|---|---|
| (공통) | 두 버전 동일. 태그 없는 항목은 모두 공통이다 |
| **[2024 전용]** | 2020에는 해당 코드/분기가 없어 테스트 대상이 아니다 |
| **[버전별 기대 결과 다름]** | 두 버전 모두 실행하되 통과 기준이 다르다 — 항목 안에 명시했다 |

Selenium은 두 버전 모두 **실행 환경이 없어 수동 QA로 대체**하기로 결정했다(spec §11). 즉 이 문서가 실질적인 최종 게이트다.

## 사전 준비

- **퀴즈 3종**
  - ① 일반 퀴즈 (문항 2개 이상)
  - ② 문항당 한 페이지 + 뒤로 못 감 (one question at a time + lock questions after answering)
  - ③ 시간 제한 2분
  - ④ **[2024 전용]** 파일 업로드 유형 문항이 포함된 퀴즈
- **계정**: 학생 1명(한글 로케일), 가능하면 영어 로케일 학생 1명. 12번을 위해 교수자 계정 1개
- **첫 진입 시 확인**
  - 개발자 도구 Network에서 **새 번들이 로드되는지** — 배포 직전에 기록해둔 번들 파일명 해시와 다른지로 판정한다(특정 날짜의 해시를 기준으로 삼지 말 것. 배포 시점이 환경마다 다르다)
  - Console에 에러 없음
  - 응시 화면 DOM에 `#quiz_warning_dialog` 요소가 존재 (없으면 모달이 조용히 열리지 않고 클릭이 삼켜진다 — 예외도 로그도 남지 않으므로 이 확인이 유일한 조기 경보다)

## P0 — 반드시 통과해야 하는 것

### 1. 미응답 제출 경고 (AC2)

- 일반 퀴즈 응시 → 문항 1개만 답 → [퀴즈 제출]
- **기대**: 네이티브 대화상자가 아닌 페이지 내부 모달. 제목 `주의`, 본문 `답변하지 않은 문제가 1개 있습니다(상세 정보는 오른쪽 사이드바 참고). 제출하시겠습니까?` — **개수가 실제와 일치**(2개 미응답이면 "2개")
- [취소] → 제출되지 않고 응시 화면 유지, 입력한 답안 그대로
- [확인] → 경고가 다시 뜨지 않고 즉시 제출 완료(점수 페이지 도달)

### 2. 경고 없는 정상 제출 (AC4)

- 모든 문항 답 → [퀴즈 제출] → 모달 없이 바로 제출

### 3. 링크 이탈 경고 (AC1)

- 응시 중 좌측 과목 메뉴(예: 과목 홈, 퀴즈 목록) 클릭
- **기대**: 모달 `이 페이지에서 나가려고 합니다. 계속 진행하시겠습니까?` + [취소]/[계속]
- [취소] → 페이지 유지, 답안 유지
- [계속] → 해당 링크로 정상 이동. **모달이 다시 뜨지 않아야 한다**(재발행 계약 — 1회성 우회 플래그가 정확히 한 번만 소비되는지 보는 항목)
- 변형: `target="_blank"` 링크에서 [계속] → **새 탭으로 열린다**(`location.href` 직접 이동이 아니라 클릭 재발행이므로 링크 속성이 보존되어야 한다)

### 4. 시간 만료 경쟁 — 이번 변경의 최대 회귀 위험 (AC7)

- 2분 퀴즈 응시 → 미응답 상태로 [제출] 눌러 **모달을 열어둔 채 아무것도 누르지 않고** 시간 만료를 기다린다
  - **주의**: 모달을 닫으면 이 테스트가 성립하지 않는다. [취소]도 [확인]도 누르지 말고 방치한다
- **기대**: 확인 모달이 **자동으로 닫히고**, 기존과 동일하게 `시간 종료!` 다이얼로그 + 10초 카운트다운 후 자동 제출
- **핵심**: 만료 시점에 모달이 닫히면서 **보류 중이던 [확인] 동작(제출 재개)이 폐기**되어야 한다. 중복 제출이 일어나면 실패다
  - 네이티브 confirm은 JS 스레드를 멈춰서 "경고가 열린 채 만료" 상태가 존재할 수 없었다. 모달은 JS를 멈추지 않으므로 **이 상태가 이번 변경으로 새로 생겼다** — 그래서 최대 위험이다
- 변형: 링크 이탈 모달을 열어둔 채 만료 → 모달 닫히고 자동 제출, **링크로 이동하지 않는다**
- **더 중요한 반대 방향 확인**: 만료 시각에 **제출이 실제로 일어나야 한다.** 경고 모달이 자동 제출을 막으면 학생이 시험을 제출하지 못하는 최악의 회귀다

### 5. 이탈 경고·답안 백업 유지 (AC8·AC9 — 의도적으로 안 바꾼 부분)

- 응시 중 답 입력 → 새로고침 또는 탭 닫기 시도 → 브라우저 네이티브 이탈 경고가 **그대로 표시**(정상)
- 나갔다가 [퀴즈 계속하기]로 재개 → 입력했던 답안이 보존되어 있음

## P1 — 분기·예외 경로

### 6. 뒤로 못 감 퀴즈 경고 3종 (AC3)

- 응시 시작 버튼 → 기존 페이지 내부 안내(변경 없음) 확인
- **공란 이동**: 현재 문항을 공란인 채 [다음] → 모달 `다음을 클릭하면 이 문제로 돌아올 수 없습니다. 공란으로 두시겠습니까?` → [취소] 시 머무름 / [확인] 시 다음 문항
- **미열람 제출**: 문항을 **건너뛰어 보지 않은 문항을 남긴 뒤** 최종 제출 → `아직 문제 N개를 보지 않았습니다. 제출하시겠습니까?`
  - 발동 조건은 "마지막 문항이 아님"이 아니라 **미열람 문항의 존재**다. 재현 시 반드시 문항을 건너뛴다

### 7. 경고가 뜨면 안 되는 링크들 (AC4)

- 오른쪽 사이드바의 문항 점프 링크(해시 링크) 클릭 → 모달 없이 해당 문항으로 스크롤
- 첨부 파일 미리보기 링크 클릭 → 모달 없이 미리보기 동작
- `no-warning` 클래스가 붙은 링크(있는 경우) → 모달 없이 이동

### 8. 보조키 클릭 (외부 리뷰 반영 사항)

- 응시 중 과목 메뉴 링크를 **Ctrl+클릭**(Mac은 Cmd+클릭), **Shift+클릭**
- **기대**: 모달 없이 새 탭/새 창으로 열리고, 응시 페이지는 그대로 남아 있음(답안 유지)
- **Alt(Option)+클릭은 이 항목에서 제외한다.** alt는 `hasModifier`에 포함하지 않기로 확정됐으므로(2020·2024 공통 수용 편차 — spec §5 D2), alt+클릭에서 **모달이 뜨고 [계속] 시 다운로드가 아니라 이동이 되는 것이 정상 동작**이다. 실패로 올리지 말 것

### 9. 모달 접근성 (AC10)

- 모달이 열릴 때 포커스가 모달 내부로 이동, Tab이 모달 안에서 순환
- ESC로 닫힘 → 제출/이동 없이 원래 화면 복귀
- **Space 키 예외**: jQuery UI Button 위젯이 적용된 다이얼로그 버튼은 **Space로 활성화되지 않는다**(마우스·Enter·ESC는 정상). 이는 **이번 변경 이전부터 존재하는 Canvas 전역 선재 결함**이며 spec §11에 알려진 한계로 기록돼 있다. 우리 코드가 관여하지 않는 기존 `cant_go_back` 시작 경고에서도 동일하게 재현된다 — **실패로 올리지 말 것**

### 10. 한글/영어 문구 (R4)

- 한글: 제목 `주의`, 버튼 `계속`·`확인`·`취소`
- 영어 로케일: `Attention`, `Continue`, `OK`, `Cancel`
- **[버전별 기대 결과 다름]** 신규 한글 키 수: **2020은 3키**(`titles.quiz_warning`·`buttons.continue_anyway`·`buttons.warning_ok`), **2024는 4키**(여기에 `confirms.file_upload_in_progress` 한글 번역 추가 — 2020에는 해당 분기 자체가 없다)
- i18n 생성 체인이 도는 환경에서만 유효하다. `ko.yml` 편집만으로는 프런트에 반영되지 않는다(키가 JS 소스에 존재 → `rake i18n:generate_js` → 웹팩 빌드 순)

### 11. 취소 후 재제출 시 경고 중복 여부 (신규 항목 — 비동기 전환으로 생긴 위험)

- one-at-a-time 퀴즈에서 최종 제출 경고를 띄운 뒤 **[취소]**
- 그 다음 **문항 이동 버튼**을 누른다(최종 제출을 다시 누르는 것이 아니다)
- **기대**: 문항 이동에서 미열람/미응답 경고가 **재발하지 않는다.** 오직 명시적으로 다시 [제출]을 눌렀을 때만 경고가 재평가된다
- 근거: `finalSubmitButtonClicked` 플래그의 리셋이 1회성으로 정확히 도는지 보는 **유일한 실환경 확인**이다. 네이티브 confirm은 동기라 이 상태가 생길 수 없었고 모달은 비동기라 새로 생긴 위험이다

### 12. **[2024 전용]** 파일 업로드 진행 중 제출

- **사전 조건**: 파일 업로드 유형 문항이 있는 퀴즈. 업로드가 끝나기 전에 제출을 눌러야 하므로 **큰 파일(수십 MB)** 을 선택하거나 **Chrome DevTools Network 탭에서 스로틀링(Slow 3G 등)** 을 걸어 업로드가 진행 중인 동안 [제출]을 클릭한다
- **기대**: `File upload is in progress. You may lose your answer before it is complete.`(한글 로케일이면 `파일 업로드가 진행 중입니다. 완료되기 전에 답안이 유실될 수 있습니다.`) 문구의 모달이 뜬다. [확인] 시 제출, [취소] 시 업로드 계속
- **우선순위 확인**: 미응답 문항이 함께 있어도 **파일 업로드 경고가 표시**된다(원 코드가 다른 분기 뒤에서 무조건 덮어쓰므로 우선순위가 가장 높다)
- 2020에는 이 분기가 존재하지 않는다 — 테스트 대상이 아니다

### 13. **[버전별 기대 결과 다름]** `end_at` 폴백 자동 제출에서 모달 폐기

`times_up` 다이얼로그를 **거치지 않는** 유일한 자동 제출 경로를 보는 항목이다. 2024는 이 경로에 방어를 넣었고 2020은 비어 있다.

**이 항목을 생략할 수 있는 경우**: 기능 플래그가 꺼져 있으면 이 코드 경로 자체가 발동하지 않는다(죽은 경로). 아래 1단계에서 체크박스가 보이지 않으면 생략하고 그 사실을 기록한다.

**사전 설정** (코드 조건이 아니라 화면에서 하는 일)

1. **기능 플래그** `timer_without_autosubmission`(표시명 *Classic Quizzes Option for Timed Quizzes without Submission*)이 루트 계정에 켜져 있어야 한다. **`state: hidden`이라 관리자 UI에 기본 노출되지 않는다.**
   - **판별법**: 별도 확인 없이 2단계에서 체크박스가 보이면 플래그가 켜진 것이다. 체크박스 자체가 `<% if @context.root_account.feature_enabled?(:timer_without_autosubmission) %>`로 감싸여 있기 때문이다(`_quiz_edit_details.erb:112`). 시간 제한을 입력한 상태에서도 안 보이면 플래그가 꺼진 것이다(시간 제한 미입력 시에는 CSS로만 숨겨진다 — DOM에 `#quiz_disable_timer_autosubmission`이 있는지로 구분 가능).
2. **퀴즈 편집**: **시간 제한 2분** 입력 → 그 아래 나타나는 **"Disable Automatic Submission"**(자동 제출 비활성) 체크박스를 체크
3. **같은 퀴즈의 사용 가능 종료일(Until / `lock_at`)을 지금부터 3~4분 후**로 설정. 시간 제한보다 뒤여야 두 시각이 달라져 조건이 성립한다
   - 코드 조건은 `timer_autosubmit_disabled && end_at != hard_end_at`이며, `end_at` = 응시 시작 + 시간 제한, `hard_end_at`(= `end_at_without_time_limit`) = 시간 제한을 뺀 계산값 ≈ `lock_at`이다(`quiz.rb:707`)

**재현 절차**

1. 학생으로 응시 시작 → 문항 1개만 답
2. **[퀴즈 제출]** 클릭 → 경고 모달이 뜬다 (또는 과목 메뉴 링크 클릭 → 이탈 모달)
3. **아무것도 누르지 않는다.** [취소]·[확인]·ESC·X를 누르면 대기 중인 동작이 폐기되어 테스트가 성립하지 않는다
4. **시간 제한(2분) 경과** — `시간 종료!` 다이얼로그가 뜨고 카운트다운이 0이 되지만 **제출되지 않는다.** 이 설정의 설계 동작이다(`shouldSubmitAtEndAt()`이 false). "결과 제출 중" 문구가 실제와 맞지 않는 것도 이 기능의 선재 UX 문제이며 이번 변경과 무관하다. `네, 알겠습니다`를 눌러도 제출되지 않고 응시 가능 상태로 돌아온다
5. 4단계에서 열려 있던 확인 모달이 닫혔다면 그것은 **항목 4의 통과**다(`showTimeUpDialog`의 방어). 13번을 보려면 `시간 종료!`를 닫고 **확인 모달을 다시 띄운 뒤** 그대로 둔다
6. **마감 시각(`lock_at`) 도달** — 여기서 `end_at` 폴백이 `submitQuiz()`를 직접 호출한다

**통과 기준 — 실질적으로는 두 가지다**

모달이 닫히는 *순간*은 페이지 이동과 겹쳐 육안으로 구분하기 어렵다. 따라서 다음 두 가지로 판정한다:

- ① **제출이 실제로 일어난다.** 모달이 열려 있어도 제출이 관철되어야 한다 — 막히면 `!submitting` 우회 불변식이 깨진 것이고 **만료 시각에 시험이 제출되지 않는 최악의 회귀**다(실패)
- ② **보류 중이던 동작이 실행되지 않는다.** 제출 후 중복 제출이나 (이탈 모달이었다면) 그 링크로의 이동이 일어나면 실패다

버전별 참고:
- **[2024]** 모달이 닫히고 제출된다

## P2 — 교수자 준비가 필요한 케이스

### 14. 퀴즈 본문의 UJS 링크 중화 (AC11)

교수자가 HTML 편집기로 링크를 삽입한 뒤 학생으로 응시한다.

- **퀴즈 설명 또는 문항 본문**에 삽입: `<a href="/courses/<id>" data-confirm="정말?">테스트</a>`
  - **기대**: `정말?` 네이티브 confirm이 뜨지 않고, 일반 이탈 모달(항목 3)을 거친다
- 변형: `<a href="#" data-remove=".x" data-confirm="정말?">x</a>`
  - **기대**: 네이티브 confirm 없음. 페이지 이탈도 없고 브라우저 기본 해시 동작만 일어난다(URL에 `#` 추가, 상단 스크롤 가능). 응시 중 콘텐츠에서 UJS remove/POST 동작이 사라지는 것은 **의도된 변경**이다
- **답안·해설 영역에도 하나 넣어 확인한다** — 중화 대상은 `.user_content` 클래스가 아니라 `#quiz-instructions`·`#questions` **서브트리 전체**다. `user_content()`는 클래스 밖에도 렌더링되므로(답안 HTML, 매칭 좌측 항목, 답안 해설, 문항 해설) **객관식 선택지 텍스트 안에 `data-confirm` 링크를 넣은 케이스**가 클래스 셀렉터 기준 실수를 잡는 유일한 확인이다

### 15. 교사 미리보기 (AC5 — 실측으로 정정된 부분)

- 교사가 [퀴즈 미리보기]로 응시
- 링크 이탈 시 **모달 없음**(현행 유지 — 미리보기 가드 안이다)
- 미응답 제출 시에는 **모달이 표시된다** — 제출 확인 핸들러는 원래부터 미리보기 가드 **밖**이라 현행에도 confirm이 떴던 경로다. 현행 보존이 정상이다
- DOM에 `#quiz_warning_dialog`가 존재하는지도 함께 확인(사전 준비 항목과 동일한 이유)

### AC6 — TLB 실기 확인 (이 문서 밖, 별도 필수 게이트)

Windows TrustLock Browser로만 확인 가능하다. 항목 1·3을 트리거해도 **OS 네이티브 다이얼로그(작업표시줄 번쩍임)가 발생하지 않아야** 한다.

- **[2020]** 2026-08-18에 **실기 확인 완료**(작업표시줄 번쩍임 소멸 — spec §11)
- **[2024]** **TLB 실기 생략으로 확정 (2026-08-19 사용자 판단)** — 일반 브라우저 QA에서 네이티브 다이얼로그가 전혀 나타나지 않음이 확인됐고, 다이얼로그를 만드는 주체는 브라우저이므로 `confirm()` 호출이 없으면 브라우저 종류와 무관하게 동일하다. TLB는 Chromium 기반이며 2020에서 같은 동작 계약으로 실기 확인이 이미 완료됐다
  - **단, AC6의 완전성은 spec §7의 운영 전제에 의존한다**: 응시 스크립트 밖 전역 스크립트에 설정 의존 네이티브 alert 경로가 3개 남아 있고(파일 미리보기 비활성 안내·미디어 저장 실패·Kaltura 비활성 안내), spec §7이 "파일 미리보기 상시 활성·Kaltura 미사용" 전제로 도달 불가·조건부로 판정했다. 이번 변경이 만든 것이 아니며 변경 대상도 아니지만, **그 전제가 바뀌면 재평가한다**
