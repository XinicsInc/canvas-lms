# PRT-109 시험 응시 중 브라우저 다이얼로그 모달 전환 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Canvas 2020 응시 화면의 네이티브 `confirm` 2곳(링크 이탈·제출 확인)을 페이지 내부 jQuery UI 모달로 교체하고, user content의 UJS 트리거 속성을 중화해 TLB(Windows)에서 OS 네이티브 다이얼로그가 뜨지 않게 한다.

**Architecture:** 새 모듈 `public/javascripts/quiz_taking_dialogs.js`에 테스트 가능한 단위(경고 메시지 결정·**판정+상태 전이 함수**·UJS 중화·모달 헬퍼)를 만들고, `take_quiz.js`의 핸들러는 판정 결과에 따라 동작하는 얇은 배선으로 바꾼다. 재진입 방지 플래그의 "정확히 1회 소비"는 판정 함수 안에서 일어나므로 QUnit으로 직접 증명된다. "일단 `preventDefault`로 막고 [확인] 시 저장해둔 동작을 정확히 한 번 재개"하는 비동기 계약(spec D2)을 따르며, `beforeunload`/`unload`와 시간 만료 분기(`shouldSubmitAtEndAt()`)는 변경하지 않는다(spec D4/D5).

**Tech Stack:** jQuery + jQuery UI dialog(기존 의존성만), QUnit/Karma(단위 테스트), Selenium RSpec(기존 시나리오 갱신), Rails i18n(`ko.yml`).

**Spec:** docs/superpowers/specs/2026-08-18-PRT-109-spec.md (코덱스 외부 리뷰 5라운드 반영본 — plan과 함께 반드시 읽을 것)

## Global Constraints

- 새 프런트엔드 의존성 추가 금지 (spec §3 제약 — jQuery UI는 기존 의존성)
- `beforeunload`(take_quiz.js:571–590)·`unload` 백업 POST(:591–612)는 **한 줄도 수정 금지** (spec D4/R5)
- 시간 만료 분기 구조 변경 금지 — `shouldSubmitAtEndAt()`(:313–320) 참이면 10초 후 자동 제출(:278–281), 거짓이면 `end_at` 폴백(:300–310) (spec D5/R8)
- 다이얼로그 본문 문구는 기존 i18n 키(`confirms.*`) 재사용, 신규 키는 모달 제목·확인 버튼 라벨만 (spec R4/D6)
- 중화 대상 셀렉터에 `.user_content` 클래스 사용 금지 — 반드시 `#quiz-instructions`, `#questions` 서브트리 기준 (spec D2)
- 주석·문서는 한글로 작성
- 커밋 메시지는 `PRT-109 <한글 제목>` + 빈 줄 + 변경 이유/내용 본문 1–3줄, `Co-Authored-By` 금지 (프로젝트 규칙)
- 교사 미리보기(`#preview_mode_link` 존재) 동작 불변 — 각 핸들러를 원래 위치에 유지: 링크 delegate는 가드(take_quiz.js:568) 안, 제출 핸들러는 원래부터 가드 밖(:864 — 현행에도 미리보기에서 제출 확인 표시됨, spec R6 실측 정정 반영). 중화(Task 3)는 미리보기 포함 전체 적용(무해·일관)

## 검증 게이트 규칙 (2회의 plan 리뷰 실측으로 확정)

- **QUnit 실행 명령**: `JSPEC_PATH=<spec경로> yarn test:karma` 를 사용한다. `yarn jspec`은 wrapper(`spec/jspec.sh:18`)가 `|| true`로 실패를 삼켜 종료 코드 0을 반환하므로 **검증 게이트로 사용 금지**. Karma가 ChromeHeadless 부재·포트 바인딩 등 환경 문제로 기동 자체가 실패하면, 그 사실을 결과에 명시하고 해당 테스트를 "환경 미검증"으로 표기한다 — 통과로 간주하지 않는다.
- **ESLint 게이트**: 신규 파일은 error 0. `take_quiz.js`는 변경 전 베이스라인이 이미 38 errors이므로 총 개수 비교로는 신규 유입을 증명할 수 없다(confirm 제거로 기존 error가 줄어 총합이 가려짐) — **변경 전/후의 (ruleId, message) 집합 차이**로 신규 위반 0을 증명한다(Task 5 Step 3의 스크립트).
- **보호 구간 게이트**: 특정 식별자 grep으로는 무변경을 보장할 수 없다 — `take_quiz.js`의 전체 diff hunk를 **허용 변경 구역 목록**과 대조한다(Task 5 Step 2). 허용 밖 hunk는 결함.
- **번들 컴파일 게이트**: Karma 미기동 시 새 import·모듈 배선이 컴파일조차 검증되지 않으므로, `rake i18n:generate_js` 후 `yarn webpack-development`를 **필수** 실행한다(Task 5 Step 4). 실행 불가 시 명시적으로 "환경 미검증" 처리한다.
- **게이트 스크립트는 자체 완결형**: 에이전트는 코드 블록마다 독립 셸을 쓸 수 있으므로 블록 간 변수 공유 금지 — `BASE` 등은 사용하는 블록 안에서 재계산한다. cleanup(`rm` 등)이 검증 실패의 종료 코드를 덮지 않도록 status를 보존한 뒤 마지막에 `exit "$status"` 한다.
- **Selenium**: 이 환경에서 실행하지 않는다. `ruby -c` 문법 확인까지만 하고 실검증은 `/verify`·CI로 이관한다. `quizzes_take_quiz_student_spec.rb`의 두 시나리오는 현재 `skip('investigate in CCI-182')` 상태라 갱신해도 실행 신호가 없음을 결과에 명기한다. 제출 [확인]/[취소] 경로는 활성 시나리오(`quizzes_taking_spec.rb` 140608 + 신규)가 커버한다.

## 단위 테스트로 커버하지 않는 잔여 영역 (근거와 대체 검증)

- **링크 경로의 DOM 액션 배선**(`preventDefault()` + 모달 호출 + `link.click()` 재발행): 판정·상태 전이·1회 소비는 `decideLinkClick` QUnit이 직접 증명하고, 남는 것은 세 줄의 액션 호출이다. 링크 이탈 Selenium 두 사례가 skip(CCI-182) 상태이므로 이 배선의 실동작은 `/verify` 수동 시나리오(응시 중 링크 클릭 → 모달 → 계속/취소)로 검증한다 — AC 대조표에 명기.
- **미리보기 모달 미등록(AC5)**: 핸들러가 기존 가드(568행) 밖으로 이동하지 않았음을 Task 5 Step 2의 hunk 대조로 검증. take_quiz.js는 최상위에서 DOM·ENV에 결합된 레거시 모듈이라 단위 로드가 비현실적.
- **시간 만료 참/거짓 제출 분기(AC7 후단)**: 무변경 코드(:272–320) — Task 5 Step 2 hunk 대조로 보장. 변경점인 `showTimeUpDialog` 첫 줄의 `cancelPendingWarning()` 호출은 같은 스텝에서 존재를 직접 검사하고, 그 함수의 "닫고 폐기" 동작은 Task 2 QUnit이 커버.
- **모달 닫힘 후 포커스 복귀(AC10 후반)**: jQuery UI dialog의 기본 동작(opener 복원)에 의존한다. headless 환경에서 포커스 복원 단정은 불안정하므로 열림 시 포커스 진입만 QUnit으로 확인하고(Task 2), 복귀는 `/verify` 수동 항목으로 이관 — AC 대조표에 명기.

import $ from 'jquery'
import I18n from 'i18n!quizzes.take_quiz'

// PRT-109: 응시 중 브라우저 네이티브 다이얼로그 제거를 위한 헬퍼 모듈.
// spec: docs/superpowers/specs/2026-08-18-PRT-109-spec.md

// 응시 본문에서 UJS 트리거 속성을 제거한다 (spec D2 중화).
// user_content()는 .user_content 클래스 밖에도 렌더링되므로
// 클래스 셀렉터가 아니라 #quiz-instructions·#questions 서브트리 기준으로 호출해야 한다.
export function neutralizeUjsLinkAttributes($roots) {
  $roots.find('a[data-confirm], a[data-method], a[data-remove]').each(function() {
    $(this)
      .removeAttr('data-confirm')
      .removeAttr('data-method')
      .removeAttr('data-remove')
      .removeData('confirm')
      .removeData('method')
      .removeData('remove')
  })
}

// 응시 중 링크 클릭 판정 + 상태 전이 (take_quiz.js 링크 delegate의 판단부).
// 기존 핸들러(원 614–649행)의 예외 순서를 그대로 보존한다.
// state는 quizSubmission 객체 — warningBypassLink·alreadyAcceptedNavigatingAway를 읽고 쓴다.
// - 'ignore'    통과, 상태 전이 없음 (다이얼로그 내부·파일 미리보기·UJS·이미 prevented·해시)
// - 'proceed'   통과, 상태 전이 수행 (no-warning: 이탈 승인 / bypass: 플래그 1회 소비 + 이탈 승인)
// - 'intercept' 이탈 경고 모달 표시 대상
export function decideLinkClick(state, link, {defaultPrevented, locationHref}) {
  const $link = $(link)
  if ($link.closest('.ui-dialog,.mceToolbar,.ui-selectmenu').length > 0) return 'ignore'
  if ($link.hasClass('no-warning')) {
    state.alreadyAcceptedNavigatingAway = true
    return 'proceed'
  }
  if ($link.hasClass('file_preview_link')) return 'ignore'
  // UJS 계열은 인터셉트하지 않는다 (spec D2 — ujsLinks와의 바인딩 순서 비결정)
  if ($link.is('[data-method], [data-confirm], [data-remove]')) return 'ignore'
  if (state.warningBypassLink === link) {
    // [계속]으로 재발행된 클릭: 정확히 1회만 통과 (재진입 방지, spec R7)
    state.warningBypassLink = null
    state.alreadyAcceptedNavigatingAway = true
    return 'proceed'
  }
  if (defaultPrevented) return 'ignore'
  const url = $link.attr('href') || ''
  let hashStripped = locationHref
  if (hashStripped.indexOf('#')) {
    hashStripped = hashStripped.substring(0, hashStripped.indexOf('#'))
  }
  if (url.indexOf('#') === 0 || url.indexOf(hashStripped + '#') === 0) return 'ignore'
  return 'intercept'
}

// 제출 시도 판정 + 상태 전이 (take_quiz.js 제출 핸들러의 판단부).
// state는 quizSubmission 객체 — warningConfirmedSubmit·submitting을 읽고 쓴다.
// - 'proceed' 제출 진행 ([확인] 재제출 플래그 1회 소비 포함, submitting 세팅)
// - 'warn'    경고 모달 표시 대상 (상태 전이 없음)
// 자동 제출(시간 만료·end_at 폴백)은 submitting=true를 먼저 세우므로 'proceed'가 된다 —
// 기존 경고 우회 불변식 보존 (spec D5).
export function decideSubmitAttempt(state, warningMessage) {
  if (state.warningConfirmedSubmit) {
    state.warningConfirmedSubmit = false
    state.submitting = true
    return 'proceed'
  }
  if (warningMessage != null && !state.submitting) return 'warn'
  state.submitting = true
  return 'proceed'
}

// 제출 시 경고 메시지 결정. take_quiz.js 제출 핸들러의 분기(원 872–911행)를
// 우선순위 그대로 순수 함수로 옮긴 것 — 반환 null이면 경고 없음.
export function getSubmitWarningMessage({
  cantGoBack,
  currentQuestionAnswered,
  finalSubmitButtonClicked,
  unseenCount,
  unansweredCount
}) {
  let warningMessage = null

  if (cantGoBack && !currentQuestionAnswered) {
    warningMessage = I18n.t(
      'confirms.cant_go_back_blank',
      "You can't come back to this question once you hit next. Are you sure you want to leave it blank?"
    )
  }

  if (finalSubmitButtonClicked) {
    if (cantGoBack) {
      if (unseenCount > 0) {
        warningMessage = I18n.t(
          'confirms.unseen_questions',
          {
            one: "There is still 1 question you haven't seen yet.  Submit anyway?",
            other: "There are still %{count} questions you haven't seen yet.  Submit anyway?"
          },
          {count: unseenCount}
        )
      }
    } else if (unansweredCount > 0) {
      warningMessage = I18n.t(
        'confirms.unanswered_questions',
        {
          one: 'You have 1 unanswered question (see the right sidebar for details).  Submit anyway?',
          other: 'You have %{count} unanswered questions (see the right sidebar for details).  Submit anyway?'
        },
        {count: unansweredCount}
      )
    }
  }

  return warningMessage
}

2. **공용 Selenium 헬퍼 누락**: 잔여 alert 스윕을 `spec/selenium/quizzes/`로만 돌려 `spec/selenium/helpers/`의 alert 계약 4곳을 놓쳤고, 외부 리뷰에서 Critical로 지적됐다. **스윕 범위는 소비자 디렉터리(helpers 포함)까지** 잡아야 한다.
3. **보조키 클릭**: 클릭 재발행으로는 ctrl/cmd/shift 의미를 보존할 수 없어 인터셉트에서 제외했다(spec D2 ④).
4. **미리보기 가드 오해**: 제출 확인 핸들러는 원래부터 `#preview_mode_link` 가드 밖이다 — spec R6/AC5를 실측에 맞춰 정정했다.
5. **검증 게이트 실측 교정**: `yarn jspec`은 실패를 삼키므로 `JSPEC_PATH=… yarn test:karma` 사용, ESLint는 총계가 아닌 (ruleId, message) 집합 비교, 보호 구간은 grep이 아닌 허용 hunk 대조, i18n 검증은 `RAILS_ENV=test rake i18n:generate_js`(development는 로그 권한으로 실패), 게이트 스크립트는 블록 간 변수 공유 금지·cleanup이 실패 코드를 덮지 않게 작성.
6. **QUnit 실행 환경**: 헤드리스 크롬은 무루트 설치 가능(`@puppeteer/browsers` + 누락 라이브러리 사용자 공간 주입 + `LD_LIBRARY_PATH` 래퍼를 `CHROME_BIN`으로). webpack의 `Module not found: ../../<JSPEC_PATH>` ERROR는 실행을 막지 않는 무해 경고다.

### 검증 결과

spec §11 참조 — QUnit 31/31, i18n 생성 체인, 정적 게이트, 운영 빌드, 수동 QA 전 항목 통과. 미검증은 Selenium 실행(CI 권장)과 TLB 실기 AC6.
