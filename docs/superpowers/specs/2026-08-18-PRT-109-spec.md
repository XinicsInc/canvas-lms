## 1. 배경 (Context)

TrustLock Browser(TLB)는 시험 감독용 잠금 브라우저다. 웹 페이지가 브라우저 네이티브 `alert`/`confirm`/`prompt`를 호출하면 TLB에서는 OS 네이티브 다이얼로그로 처리되는데, Windows에서 이 다이얼로그가 뜨는 순간 작업표시줄이 노출되고 포커스가 이탈해 다른 앱을 볼 수 있게 된다 — 잠금 브라우저의 차단 목적이 훼손된다.

Canvas 클래식 퀴즈 응시 화면은 문제를 덜 풀고 제출하거나 응시 중 링크를 클릭하는 등의 상황에서 네이티브 `confirm`을 사용한다. 반면 같은 화면의 다른 안내(응시 시작 전 `cant_go_back` 경고, 시간 만료, 재로그인)는 이미 페이지 내부 jQuery UI 다이얼로그를 쓰고 있다. 이 선례와 동일하게, 응시 중 네이티브 다이얼로그를 페이지 내부 UI로 교체한다.

당사는 Canvas 2020(`/data/canvas`)과 Canvas 2024(`/data/canvas2024`) 두 릴리스를 지원하며, 두 코드베이스는 같은 문제를 서로 다른 파일에 독립적으로 갖고 있다. 이 spec은 두 버전 공통의 동작 계약이며, 구현은 Canvas 2020을 먼저 완료한 뒤 같은 계약으로 Canvas 2024를 진행한다 (사용자 확정 — design Q1).

## 2. 문제 (Problem)

Canvas 응시 화면(`take_quiz`)에서 네이티브 다이얼로그가 발생하는 지점 (2026-08-14 실측, 2026-08-18 재검증). **이 문서의 모든 행 번호는 구현 전 기준(2020: `e18707ac33`)이며, 구현 후에는 이동했다**:

- **P1. 링크 이탈 확인 `confirm`** — 응시 중 페이지 안의 `<a>` 클릭 시 "이 페이지에서 나가려고 합니다. 계속 진행하시겠습니까?" 네이티브 confirm.
  - 2020: `public/javascripts/take_quiz.js:637` / 2024: `ui/features/take_quiz/jquery/index.js:631`
- **P2. 제출 확인 `confirm`** — 폼 제출 시 조건 분기된 경고를 네이티브 confirm 하나로 표시.
  - 분기: ① `cant_go_back` 퀴즈에서 현재 문항 공란인 채 다음 이동(`confirms.cant_go_back_blank`) ② `cant_go_back` 퀴즈 최종 제출 시 미열람 문항 존재(`confirms.unseen_questions`) ③ 일반 퀴즈 최종 제출 시 미응답 문항 존재(`confirms.unanswered_questions`) ④ (2024 전용) 파일 업로드 진행 중 제출(`confirms.file_upload_in_progress`)
  - 2020: `take_quiz.js:914`(분기 872–911) / 2024: `index.js:924`(분기 878–921)
- **P3. `beforeunload` 네이티브 경고** — 탭 닫기·새로고침·주소 이동 시 브라우저 네이티브 이탈 경고(`confirms.unfinished_quiz`).
  - 2020: `take_quiz.js:571–590` / 2024: `index.js:565–584`
  - P1·P2와 달리 브라우저 보안상 커스텀 페이지 모달로 대체 불가. TLB 실측 결과 네이티브 다이얼로그가 표시되지 않아 범위 제외로 확정(§5 D4).

응시 스크립트(`take_quiz.js`) 자체에는 `alert`/`prompt` 직접 호출이 없다. 다만 모든 페이지에 로드되는 전역 스크립트에는 **설정 의존 네이티브 alert 경로**가 남아 있다 — 상세와 이 배포에서의 판정은 §7 참조. 퀴즈 저작 화면의 alert/confirm은 "시험 중" 범위 밖이다(§7).

## 3. 요구사항 (Requirements)

- **R1**: 응시 중 링크 이탈 확인(P1)을 페이지 내부 모달 다이얼로그로 교체한다. [취소]는 현재 페이지 유지, [계속]은 원래 링크 동작을 재개한다.
- **R2**: 제출 확인(P2)을 페이지 내부 모달 다이얼로그로 교체한다. 기존 분기 조건·메시지·우선순위를 그대로 유지한다. [취소]는 제출 중단, [확인]은 제출을 진행한다.
- **R3**: 교체는 TLB 여부와 무관하게 전 브라우저 공통으로 적용한다 (사용자 확정 — design Q3).
- **R4**: 다이얼로그 본문 문구는 기존 i18n 키(`confirms.navigate_away`, `confirms.cant_go_back_blank`, `confirms.unseen_questions`, `confirms.unanswered_questions`, 2024의 `confirms.file_upload_in_progress`)를 재사용한다. 버튼 라벨은 기존 공용 키(예: `#buttons.cancel` — 같은 파일의 `#deauthorized_dialog`가 사용 중) 재사용을 우선하고, 신규 키는 공용 키로 대체할 수 없는 것(모달 제목, [계속]류 라벨 등)에 한정한다. 재사용/신규 키의 확정 목록은 plan에서 정한다. **구현 확정 결과(2020)**: 신규 3키 — `quizzes.take_quiz.titles.quiz_warning`(주의), `quizzes.take_quiz.buttons.continue_anyway`(계속), `quizzes.take_quiz.buttons.warning_ok`(확인). [취소]는 기존 공용 키 `#buttons.cancel` 재사용. Canvas i18n 관례상 영어는 소스의 `I18n.t('key', 'English default')` 인라인 기본값이 원문이며(생성물 자동 추출 — 수동 편집 없음), `config/locales/ko.yml`(ERB·JS 공용 로케일 원천, `quizzes.take_quiz` 스코프)에 한글 번역만 추가한다. ko.yml 편집만으로는 프런트에 반영되지 않는다 — 생성 체인은 ① 키가 JS 소스에 존재(i18nliner가 `config/locales/generated/js_bundles.json`으로 추출; 소스에 없는 키는 번역이 있어도 탈락) ② `rake i18n:generate_js`가 비-en 로케일 번역을 스코프별로 slice해 `public/javascripts/translations/quizzes.take_quiz.js` 생성 ③ 웹팩 빌드(`js:webpack_*`가 ②에 의존) 순이며, en은 번역 파일에 포함되지 않고 인라인 기본값으로 표시된다.
- **R5**: `beforeunload`(P3)는 변경하지 않는다 — TLB 실측 결과 범위 제외로 확정(§5 D4). 페이지 이탈 시 답안 백업 POST(`unload` 핸들러)도 그대로 유지한다.
- **R6**: 교사 미리보기 모드(`#preview_mode_link` 존재) 동작은 현행과 동일하게 유지한다. (구현 중 실측 정정: 미리보기 가드(take_quiz.js:568–650)는 링크 이탈 경고·`beforeunload`에만 적용되고, 제출 확인 핸들러(:864)는 원래부터 가드 밖이라 현행에도 미리보기에서 표시된다. 따라서 미리보기에서 링크 이탈 모달은 표시되지 않고, 제출 확인 모달은 현행 confirm과 동일한 조건에서 표시된다. 또한 user content의 UJS 속성 중화(D2)는 가드 밖 `ready` 핸들러에서 수행하므로 미리보기에도 적용된다 — 저작 기능에 영향이 없고 동작이 일관되도록 의도한 것이다.)
- **R7**: 확인 후 재개된 동작(링크 이동·폼 제출)이 경고 로직을 다시 타지 않아야 한다(재진입 방지).
- **R8**: 시간 만료 흐름은 현행을 유지한다 — 만료 시 `#times_up_dialog`가 표시되고, 제출 시점은 현행 설정 분기를 따른다(`shouldSubmitAtEndAt()` 참이면 10초 카운트다운 후 자동 제출, 거짓이면 별도 `end_at` 폴백 대기). 확인 모달이 열려 있으면 times_up 표시 시점에 닫고, 보류 중이던 재개 동작(링크 이동·수동 제출 콜백)은 폐기한다. 자동 제출은 어느 경로로 발화하든 확인 모달·경고에 막히지 않아야 한다(§5 D5).
- **제약**: 새 프런트엔드 의존성을 추가하지 않는다(양쪽 응시 플로우 모두 jQuery UI 기반 — 2020은 React/InstUI 관용구 부재, 2024 응시 플로우도 React 미도입). 주석·문서는 한글로 작성한다. Canvas 2020을 먼저 구현·검증 완료한 뒤 Canvas 2024를 진행한다.

## 4. 수용 기준 (Acceptance Criteria)

- **AC1**: 응시 중 페이지 내 일반 링크 클릭 시 네이티브 confirm이 아닌 페이지 내부 모달이 표시된다. [취소] 시 페이지에 머무르고 답안 상태가 유지되며, [계속] 시 해당 링크로 이동한다(`target` 등 원래 링크 속성이 존중된다). UJS 계열 링크(`data-method`/`data-confirm`/`data-remove`)는 모달 인터셉트 범위에서 제외되어 UJS 동작을 따르되, user content 영역에서는 해당 속성이 초기화 시 중화되어 일반 링크로 취급된다(§5 D2).
- **AC2**: 미응답 문항이 있는 상태로 제출 버튼 클릭 시 페이지 내부 모달이 표시되고, 미응답 개수가 기존 문구 그대로 보간된다. [취소] 시 제출되지 않고 응시 화면이 유지되며, [확인] 시 제출이 완료된다.
- **AC3**: `cant_go_back` 퀴즈의 공란 다음 이동 경고와 미열람 문항 제출 경고도 AC2와 동일하게 모달로 동작한다. (2024 구현 시 파일 업로드 진행 중 경고 포함)
- **AC4**: 현행 기준으로 이동/제출에 경고가 없는 경로(no-warning 링크, 파일 미리보기 링크, 해시 앵커, 미응답 없는 제출, jQuery UI 다이얼로그 내부 링크)는 모달 없이 기존과 동일하게 동작한다.
- **AC5**: 교사 미리보기 모드 동작이 현행과 동일하다 — 링크 이탈 모달은 표시되지 않고(가드 내), 제출 확인은 현행 confirm이 표시되던 조건 그대로 모달이 표시된다. 현행 대비 새로 생기는 경고는 없다.
- **AC6**: TLB(Windows)에서 응시 중 링크 이탈·미응답 제출을 시도해도 OS 네이티브 다이얼로그가 뜨지 않아 작업표시줄 노출·포커스 이탈이 발생하지 않는다.
- **AC7**: 확인 모달이 열린 상태에서 퀴즈 시간이 만료되면 현행과 동일하게 동작한다 — `shouldSubmitAtEndAt()`이 참이면 `times_up` 다이얼로그와 10초 카운트다운을 거쳐 자동 제출되고, 거짓이면 현행 `end_at` 폴백 흐름을 따른다. 어느 경우든 만료 전 보류 중이던 링크 이동·제출 재개 동작은 실행되지 않는다.
- **AC8**: 페이지 이탈(탭 닫기 포함) 시 답안 백업 POST가 현행과 동일하게 발생한다.
- **AC9** (확정 — 2026-08-18 실측): P3(`beforeunload`)은 변경 없음으로 종결한다. 일반 브라우저에서 현행 이탈 경고가 그대로 동작하고, TLB에서는 실측대로 네이티브 다이얼로그가 표시되지 않는다.
- **AC10**: 모달 표시 중 키보드 포커스가 모달 내부로 이동하고, ESC 또는 [취소]로 닫으면 원래 화면 흐름으로 복귀한다. (예외: 버튼의 Space 활성화는 §11의 선재 제약에 해당 — 마우스 클릭·Enter·ESC는 정상)
- **AC11**: 퀴즈 설명·문항·답안·해설 등 user content에 `data-confirm`(또는 `data-method`/`data-remove`) 링크가 포함돼 있어도 응시 중 네이티브 confirm이 표시되지 않는다. 중화된 링크는 일반 링크와 동일한 규칙을 따른다 — 페이지 이탈이 발생하는 href면 이탈 경고 모달을 거치고, 해시형 href(`#`)면 모달 없이 브라우저 기본 해시 동작을 따른다(현행 일반 해시 링크와 동일 — 이탈·네이티브 다이얼로그 없음, §5 D2 중화).

## 5. 설계 결정 (Design Decisions)

상세 비교와 근거는 design 문서(§2–§4) 참조. 요약:

- **D1. 대체 UI는 jQuery UI `.dialog()` 직접 호출 방식** — 같은 파일의 `#times_up_dialog`/`#deauthorized_dialog` 선례와 동일. `element_toggler`/`data-turn-into-dialog` 관용구는 마크업 사전 연결형이라 이벤트 핸들러 중간의 동적 confirm 대체에 부적합, React/InstUI는 응시 플로우에 관용구가 없어 과도(탈락 근거는 design §3).
- **D2. 동기 → 비동기 전환 계약** — 네이티브 confirm은 동기, 모달은 비동기다. 두 지점 모두 "일단 `preventDefault`로 막고, [확인] 시 저장해둔 동작을 재개"하는 패턴으로 전환한다. 재개 시 재진입 방지 플래그로 경고 스킵(R7). 링크는 기존 `alreadyAcceptedNavigatingAway` 플래그를 [계속] 시점에 설정해 `beforeunload`와의 기존 연동을 보존한다.
  - **링크 재개의 정밀 계약**: 현행 링크 핸들러(take_quiz.js:614–649)는 `alreadyAcceptedNavigatingAway`를 검사하지 않으므로, 재개를 위해 클릭을 재발행하면 모달에 다시 진입하고, 반대로 `location.href` 직접 이동은 `target`·`data-method`(UJS — `app/coffeescripts/behaviors/ujsLinks.js`의 delegated 핸들러) 의미를 잃는다. 따라서 [계속]은 **1회성 경고 우회 플래그를 세우고 원래 클릭 동작을 정확히 한 번 재발행**하며, 링크 핸들러는 이 플래그를 검사·소비해 통과시킨다(`location.href` 직접 이동 금지). **보조키(ctrl/cmd/shift) 클릭은 인터셉트하지 않는다**(구현 리뷰 반영) — 새 탭/창으로 열려 응시 페이지를 떠나지 않으므로 이탈 경고 대상이 아니고, 재발행으로는 보조키 의미를 보존할 수 없어 브라우저 기본 동작을 그대로 통과시킨다.
  - **재발행 방식의 의도적 동작 변경(위험 수용, 구현 리뷰 반영)**: 원본 네이티브 confirm은 하나의 클릭 이벤트 안에서 동기적으로 판단했지만, 재발행 방식은 최초 클릭과 [계속] 재발행에서 클릭 파이프라인이 각 1회씩 실행된다. 따라서 ① 대상/조상 요소에 부착된 다른 click 리스너가 두 번 실행될 수 있고 ② 재발행 클릭을 다른 리스너가 `preventDefault`하면 이동 없이 우회 플래그가 소비되고 이탈 승인 상태(`alreadyAcceptedNavigatingAway`)가 남아 이후 실제 이탈 시 `beforeunload` 경고가 생략될 수 있다. 응시 화면의 인터셉트 대상 링크(일반 콘텐츠 링크 — UJS·파일 미리보기·미디어 링크는 제외 규칙 적용)에는 이런 리스너가 현재 존재하지 않음을 확인했으며, 이 잔여 위험은 수용한다. 콘텐츠 링크에 side-effect 리스너가 도입되면 재평가한다.
  - **UJS 계열 링크는 인터셉트 대상에서 제외**: `ujsLinks`는 idle-time 비동기 chunk로 로드되어(app/jsx/main.js:92 → runOnEveryPageButDontBlockAnythingElse — "다른 js_bundle보다 먼저 실행된다는 보장 없음" 주석 명시) take_quiz delegate와의 바인딩 순서가 비결정적이고, UJS 핸들러는 `isDefaultPrevented()`를 검사하지 않아 어느 순서에서도 모달 인터셉트와 안전하게 조합되지 않는다. 현행 네이티브 confirm에서도 순서에 따라 confirm 없이 POST되거나 취소 후에도 POST되는 동일 결함이 이미 존재한다. 따라서 `a[data-method]`, `a[data-confirm]`, `a[data-remove]`는 이탈 경고 모달의 인터셉트 대상에서 제외하고 UJS 동작에 위임한다(이중 POST 방지·결정적 동작 확보 — 현행 대비 보호 회귀 아님). 응시 화면 뷰(take_quiz.html.erb)에 해당 링크는 없음을 확인했다. 재발행 재개 계약은 일반 링크에만 적용한다.
  - **user content 경유 유입 차단(중화)**: 퀴즈 설명·문항 텍스트는 `user_content`로 렌더링되고(take_quiz.html.erb:47, _display_question.html.erb) Canvas sanitizer가 임의 `data-*` 속성을 허용하므로(gems/canvas_sanitize/.../canvas_sanitize.rb:115 `:data`), 교수자 작성·가져오기 콘텐츠에 `a[data-confirm]` 링크가 존재할 수 있으며 UJS는 이 속성에 네이티브 `confirm()`을 직접 호출한다(ujsLinks.js:46–50) — AC6 위반 경로. 따라서 응시 페이지 초기화 시 콘텐츠 영역 링크의 UJS 트리거 속성(`data-confirm`·`data-method`·`data-remove`)을 제거한다.
    - **경계**: 중화 대상은 `.user_content` 클래스가 아니라 user content가 렌더링되는 응시 본문 전체다 — 퀴즈 설명(`#quiz-instructions`)과 문항 목록(`#questions`) 서브트리의 모든 `a`. `user_content()`는 `.user_content` 클래스 밖에도 렌더링되므로(답안 HTML `.answer_html`, 매칭 `.answer_match_left_html`, 답안 해설 `.answer_comment_html`, 문항 해설 `.question_comment_html` — `_display_answer.html.erb:90·98·174`, `_display_question.html.erb:445`) 클래스 셀렉터 기준 중화는 금지한다.
    - **시점**: 중화는 본문 노출 전에 완료한다 — 응시 본문은 `.loaded` 표시(take_quiz.js:1038–1041의 ready 핸들러 `$('.loaded').show()`)까지 숨겨져 있으므로, 같은 초기화 사이클에서 이 표시보다 먼저 실행한다. 속성이 클릭 전에 사라지므로 바인딩 순서와 무관하게 결정적이다.
    - **중화 후 동작**: 중화된 링크는 일반 링크 규칙을 그대로 따른다 — 페이지 이탈이 발생하는 href면 이탈 경고 모달을 거치고, 해시형(`href="#"` — UJS `data-remove`의 전형, ujsLinks.js:74 예시)은 기존 해시 예외(take_quiz.js:634)를 따른다 — 해시 예외는 `preventDefault` 없이 반환하므로 모달 없이 **브라우저 기본 해시 동작**(URL `#` 추가, 상단 스크롤 가능)이 남으며, 이는 현행 콘텐츠 내 일반 `href="#"` 링크와 동일한 동작이다. 페이지 이탈도 네이티브 다이얼로그도 발생하지 않으므로 AC6 목적에 부합하며, 응시 중 콘텐츠에서 UJS remove/POST 동작이 사라지는 것은 의도된 변경이다.
    - **크롬 영역**: 조건부 하단 크롬에 `data-method` 링크가 존재하나(`app/views/layouts/_fixed_bottom.html.erb:49·50·68` — 학생 보기 초기화/종료·가장 종료, 교수자 전용 노출) `data-confirm`이 없어 네이티브 다이얼로그를 만들지 않으며, UJS 제외 규칙에 따라 현행 UJS 동작을 유지한다.
- **D3. 전 브라우저 공통 적용** — TLB 감지 분기 없이 항상 모달 사용(R3). 코드 경로 단일화, 일반 브라우저 UX 일관성.
- **D4. `beforeunload`는 범위 제외로 확정 (사용자 확정 — design Q2, 2026-08-18 TLB 실측)** — 실측 결과: Windows TLB에서 리프레시 버튼은 있으나 `beforeunload` 네이티브 다이얼로그가 표시되지 않고, 리프레시 자체도 동작하지 않는다. 이는 Electron 기본 동작(앱이 `will-prevent-unload`를 처리하지 않으면 다이얼로그 없이 unload가 조용히 취소됨)과 정합하며, Canvas의 `beforeunload` 핸들러가 TLB 안에서는 응시 중 리프레시를 무음 차단하는 효과를 낸다.
  - 따라서 P3은 포커스/작업표시줄 문제를 일으키지 않으므로 변경하지 않는다(현행 유지). 일반 브라우저의 이탈 경고 보호도 그대로 보존된다.
  - 부수 관찰: TLB에서 리프레시가 무음 차단되는 현상은 이 핸들러의 부작용이나, 시험 중 리프레시 억제는 감독 목적상 수용 가능한 동작으로 판단한다. 별도 개선이 필요해지면 TLB 측(`will-prevent-unload` 처리)의 이슈로 다룬다.
- **D5. 시간 만료 우선** — 근거: 현행 코드가 이미 "만료 자동 제출은 경고를 우회"하도록 설계돼 있다. 자동 제출 경로 2곳(2020 기준 take_quiz.js:278–281 카운트다운 만료, :300–310 end_at 폴백)은 `submitting = true`를 먼저 세우고 제출하며, 경고 confirm의 가드(:913 `warningMessage != undefined && !quizSubmission.submitting`)가 이를 통과시킨다. 다만 현재는 네이티브 confirm이 JS 스레드를 멈춰 "경고가 열린 채 만료" 상태가 존재할 수 없었는데, 모달은 JS를 멈추지 않으므로 이 상태가 새로 생긴다. 따라서 모달 구현은 `!submitting` 우회 불변식을 반드시 보존해야 하며(위반 시 만료 시각에 시험이 제출되지 않는 회귀 — AC7), **만료 시 흐름 자체는 현행 유지**한다: `showTimeUpDialog`(:408–430)가 `countDown = now + 10초`를 걸고 `#times_up_dialog`를 표시하며, 10초 후 자동 제출(:278–281)은 `shouldSubmitAtEndAt()`(:313–320)이 참일 때만 발화한다. 타이머 자동제출 비활성(`timer_autosubmit_disabled`, `end_at` 불일치) 시에는 :300–310의 `end_at` 폴백이 제출을 담당한다 — 이 분기 구조를 생략·단축·변경하지 않는다. times_up 표시 시점에 열려 있는 확인 모달은 닫고, 보류 중이던 재개 콜백(링크 이동·수동 제출)은 폐기한다 — 만료 이후 사용자의 이전 [계속] 의사로 이동·제출이 재개되면 안 된다.
- **D6. 문구 재사용** — 본문은 기존 `confirms.*` 키 재사용으로 번역 자산을 보존한다. 신규 키는 모달 제목·버튼 라벨로 한정한다(R4).
- 외부 의존성 추가 없음. 데이터 모델·API 변경 없음.
